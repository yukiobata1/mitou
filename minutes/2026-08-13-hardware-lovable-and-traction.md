# Hardware Lovable案・トラクションの重要度

- 日時: 2026-08-13（Asia/Tokyo）
- 情報提供者: 小幡有生氏
- 記録者: Codex
- 目的: 新案「ハードウェア版Lovable」の記録と、未踏アドバンストにおけるトラクションの位置づけの確認

## 新しいアイデア

- 従来は専門家と複数ツールが必要だったハードウェア開発を、自然言語から生成・シミュレーションし、デバイスを作れるようにする。
- 仮称: ハードウェア版Lovable。
- 現時点では、生成対象が回路、PCB、筐体、組込みソフトウェア、部品表、製造データのどこまでか未確定。

## 公式要件から確認したトラクションの位置づけ

- 売上、利用者数、資金調達等のスタートアップ型トラクションは、応募要件・審査基準に明示されていない。
- 企画・構想段階またはプロトタイプ開発中の案件が公募対象であり、プレプロダクト・プレ売上でも応募可能。
- 審査基準は未踏性、ビジネス発展性または高い社会的意義、開発実現性。
- 詳細資料では、存在する場合の現状プロトタイプ、市場・ユーザー・ニーズ、競合比較、期間中の事業化・社会実装活動、終了後の人員・経費・売上計画等を説明する。
- したがってトラクションは独立した審査項目ではなく、ニーズ、優位性、実現性を裏づける証拠として作用する。

## 採択事例からの分析

- 2026年度上期のエージェンティック音声入力は、日本語音声LLMのプロトタイプを実現可能性の根拠として評価された一方、事業化計画・競合対策は今後の課題と明記された。売上がなくても、強い技術試作で採択され得る。
- 2025年度下期の掘削自動化は、全国90件超の現場調査と、制御装置・センサー・UIの試作が顧客ペインと実現性の証拠として高く評価された。
- 2025年度上期の遠隔医療は、プロトタイプ、専門医との連携、開発から検証・事業化までの道筋が評価された。
- 2024年度の農作物選別は、現地調査、プロトタイプ、協力者獲得が評価された。
- 過去には、ビジネス検討がまだこれからでも、技術試作、没頭力、実現能力を理由に採択された案件がある。

## 判断

トラクションの重要度を一律に表すと誤解を生むため、種類別に扱う。

| トラクション | 重要度 | Hardware Lovable案での証拠 |
|---|---:|---|
| 技術トラクション | 5/5 | 自然言語から実際に設計・シミュレーション・製造できる試作、専門家との比較 |
| 課題トラクション | 4/5 | ハードウェア開発者への観察・インタビュー、工数・失敗原因の記録 |
| 現場・協力者トラクション | 4/5 | 設計パートナー、部品・製造・検証協力者、実証合意 |
| 利用トラクション | 3/5 | 外部ユーザーが自力でデバイスを完成、反復利用した記録 |
| 売上トラクション | 2/5 | 有償設計・有償PoC。あれば強いが、採択の前提ではない |
| 資金調達・SNS・待機リスト | 1/5 | 単独では技術的新規性・実現性をほぼ証明しない |

本案では、申請までに大量ユーザーや売上を追うより、次の証拠を優先する。

1. 3種類程度の限定されたデバイスで、自然言語要求から成果物まで通す。
2. 回路・筐体・ファームウェア・シミュレーション間の整合性を自動検証する。
3. 専門家の通常工程と比べ、所要時間、手戻り、設計違反、実機成功率を測る。
4. ハードウェア開発経験者10〜15人に課題ヒアリングを行う。
5. 2〜3組の設計パートナーに外部利用してもらい、少なくとも1組が実機を完成させる。

## 保留事項

- 対象ユーザー: 非専門家、ソフトウェアエンジニア、スタートアップ、企業設計者のどこか。
- 対象デバイス: センサノード、ウェアラブル、ロボット周辺機器等のどこまでに限定するか。
- 生成範囲: 要件、部品選定、回路、PCB、筐体、ファームウェア、シミュレーション、製造データ。
- 技術核: 生成UIではなく、複数領域をまたぐ中間表現、制約充足、検証、sim-to-real補正のどれに置くか。
- チーム内に回路・機械・組込み・製造の実績があるか。なければ、不可欠な開発者または外部協力者が必要。
- 小幡氏の会社との事業・知財の境界。

## 次のアクション

- [ ] 対象デバイスを3カテゴリ以内に絞る
- [ ] 既存の自然言語CAD・回路・PCB・組込み生成ツールを調査する
- [ ] 既存工程で最も時間がかかる境界部分を10人以上に聞く
- [ ] 2週間で作るend-to-end試作と比較ベンチマークを定義する
- [ ] 3人の現有チームで欠けているハードウェア能力を棚卸しする
