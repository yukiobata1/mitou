## 1. 提案の背骨（全員がこの5行を同じ言葉で言えること）

1. **誰が困っているか**: 複数ベンダーの搬送システムが混在し、止められず交換もできない工場・倉庫。最初の現場は半導体工場。
2. **何が起きているか**: ベンダーの境界（合流・交差・ストッカ前・受け渡し口）だけ誰も最適化しておらず、保守的な待ち・デッドロック・人手介入が集中する。
3. **なぜ既存で解けないか**: 既存の統合手段は、ベンダー側の規格対応か、全機を中央制御できることが前提。既設のブラックボックス機では成立しない。
4. **何を作るか**: 機体にもベンダーソフトにも手を入れず、観測した応答から能力をオンライン同定し、競合した局所だけを調停する上位ランタイム。学習は効率、安全は独立層。
5. **8か月でどこまで**: シミュレーションで保守的運用比の改善を数値で示し、実ログのshadow運用1拠点、限定区画の実運用1件。

審査3軸との対応: 未踏性 = 3と4 / 事業性 = 1と2（＋インタビュー） / 実現性 = 5（＋④の実績と応募前デモ）。

## 3. インタビューの書き方（強く、かつ突かれても崩れない形）

- 社名を出すのは先方の許諾がある場合だけ。なければ属性で書く（「半導体向け製造ソフトウェア企業」「搬送システムベンダー系企業」）。属性でも審査上の効力はほぼ変わらない。
- 数値は裸で書かない。「搬送効率5%改善」→ 誰が、どの規模の工場で、何の指標（搬送時間／搬送能力／サイクルタイム）を、何と比べて。条件が分からなければ「過去事例として5%程度の改善が語られた（条件は未確認）」と書く。二次審査で最初に聞かれるのはここ。
- 「聞いた事実」「そこからの推論」「チームの仮説」を分ける。推論を相手の発言にしない。
- 合意は段階を正確に：面談した ＜ 課題に共感を得た ＜ 継続面談の約束 ＜ ログ提供の意向 ＜ 文書（LOI）。今の段階を書き、次の段階を期間中のマイルストーンにすれば、弱い合意でも計画の具体性として効く。
- 応募前の5日間で、インタビュー先へ「この理解で合っているか」を確認するメールを1本送ると、事実の確度と関係の段階が同時に上がる。

### インタビュー先へ至急確認すること（9/20の半導体調査で判明。提案の成否を分ける）

調査の結論: 300mm前工程のOHT網は、確認できた範囲では単一ベンダーで完結しており、ベンダー横断の調整層はMCSとして既に存在する（Applied Materialsは導入250件超）。上位に公開される操作は搬送指示の単位で、車両単位の操作は各社制御の内側にある。つまり半導体で「他社機同士の合流・交差の調停」を主張すると、業界人から「それはMCSの仕事」「そんな境界はない」と言われる。骨子は、後工程・200mm・OHT＋AMR混在の受け渡し点を対象に、診断（観測のみ）→ 調停の2段階へ修正済み。これが現場の実感と合うかを聞く。

ムラタシステムへ:
1. 他社機器との境界（ストッカ口、リフタ、OHTとAMRの接続、共有通路）で、実際に待ち・詰まり・人手介入は起きているか。頻度と影響は。
2. 上位システムから出せる命令の実際の一覧。車両・搬送単位で待たせる、順序を変える、といった操作の余地はあるか。
3. 位置履歴・イベントログを外部の診断ソフトへ出すことは可能か。境界の制御を外部へ渡す余地は。

camLineへ:
1. 顧客工場で複数ベンダーの搬送が混在する頻度と形態（棟別か、装置種別か、同じ通路・軌道か）。
2. MES/MCSから搬送装置の内部の待ちはどこまで見えているか。見えないことで困っている具体例。
3. 「5%改善」等の過去事例は、何の指標を、どの規模で、何と比べた値か。

聞いた結果、境界の問題が実在しない・操作口が全くないと分かった場合は、物流倉庫を第一市場に切り替える（①と⑤の入れ替えで対応可能）。

## 6. 未決事項

1. 最初の現場を半導体に置く判断（インタビューの証拠がそこにあるため暫定採用）。物流倉庫を主にする場合は①と⑤の入れ替えで対応可能。
2. 主軸は「ビジネス発展性」で書いている。
3. 第一希望PM。実機・現場寄りなら吉崎PM・平野PM、手法寄りなら原田PM（8/31調査）。半導体・製造の文脈が入ったため再検討する。
4. チームに半導体搬送の実務経験がないことへの補い方（協力者の明記可否）。
5. **「複数ベンダーの搬送機が混在して困っている拠点」の割合を示す公的統計は見つからなかった**（9/20調査）。問題の存在はインタビューで裏づけるしかない。インタビュー先への確認メールで「境界で待ち・介入が起きているか、その頻度」を必ず聞く。
6. **最大の競合はInOrbit**（ベンダーシステムの上に載る異種フリート交通管理、30以上のブランド、2026-09-15にOSS版OpenRobOps公開）。二次審査で「InOrbitと何が違うか」を30秒で答えられるようにする：相手は接続と集約、こちらは接続後も一時停止程度しか効かないブラックボックス相手の同定と調停。先方が非公開で同じことをやっていないとは確認できていない。
